We&#x27;ve released new versions of the client SDKs and the ant CLI that send API version 2026-10-21 by default: Python SDK 2.0.0, TypeScript SDK 1.0.0, C# SDK 13.0.0, Go SDK 2.0.0, Java SDK 3.0.0, PHP SDK 1.0.0, Ruby SDK 2.0.0, and ant CLI 2.0.0. October 20, 2026  The Claude Tag API is available in beta for Claude Enterprise organizations with the experimental-claude-tag-2026-10-21 beta header. Its /v1/organizations/claude_tag/ endpoints read and change Claude Tag settings on Slack channels and Slack workspaces, show which settings apply in a channel and where each comes from, and attach Access bundles. Call it with an Admin API key that your primary owner creates in claude.ai with the read:claude_tag or write:claude_tag scope. It is not available to Claude Platform (Claude Console) organizations. October 20, 2026  Inference hooks are out of beta for Claude Enterprise organizations. We&#x27;ve launched user profiles , so you can tell Anthropic which of your end customers each API request is for. If you operate a platform or gateway, or resell API access, a safety enforcement action can then apply to one end customer instead of your whole organization. The SDK and the ant CLI support the new /v1/user_profiles endpoints . We&#x27;ve added organization webhooks to the Admin API , in beta with the webhooks-2026-10-07 beta header. Its /v1/organizations/webhooks endpoints register webhook endpoints for two event types: one for when Anthropic restricts or bans one of your organization&#x27;s user profiles, and one for when the restriction or ban ends. To request access, contact your Anthropic account team. Organization admins can now turn off web fetch for their organization on the Capabilities page of the Claude Console. With web fetch off, a Messages API request that includes the web fetch tool fails with a 400 error. In a Claude Managed Agents session, web_fetch calls return an error result to the agent instead. With web fetch on, admins can also set allowed or blocked domains for web fetch on the same page. See How to use web fetch and Domain filtering . In Claude Managed Agents, the web_fetch tool now follows your organization&#x27;s web fetch domain restrictions set on the Capabilities page of the Claude Console. A URL, including one reached by a redirect, must pass both the organization&#x27;s list and the allowed_domains or blocked_domains list on the agent&#x27;s web_fetch tool. See Restrict web search and web fetch domains . In Claude Managed Agents, sessions follow your organization&#x27;s web search settings on the Capabilities page of the Claude Console: the Allow web search setting since October 6, and its web search domain restrictions since October 14. The agent receives only the search results that both the organization&#x27;s domain restrictions and the allowed_domains or blocked_domains list on the agent&#x27;s web_search tool allow. October 9, 2026  You can now let a Claude Managed Agents agent use dynamic workflows , in beta with the managed-agents-2026-04-01 beta header. For work with many pieces, such as reviewing hundreds of documents, the agent can write a workflow. A workflow is a program that runs many agents in phases and combines their results. The server runs it in the background as a workflow run. To turn dynamic workflows on , set the agent&#x27;s multiagent field to {&quot;type&quot;: &quot;multiagent_20261001&quot;, &quot;workflows&quot;: {&quot;type&quot;: &quot;enabled&quot;}} . To guide the agent, tell it in its system prompt when to start a run. Follow each run through workflow_run.* events on the session&#x27;s event stream. See Workflow runs . We&#x27;ve launched Claude Haiku 5.5 ( claude-haiku-5-5 ), our most capable model tuned for high-volume and latency-sensitive work. It has a 1M token context window , 128k max output tokens, and adaptive thinking with the effort parameter . It&#x27;s available on the Claude API, Claude in Amazon Bedrock , Claude Platform on AWS , Claude on Google Cloud , and Claude in Microsoft Foundry . See What&#x27;s new in Claude Haiku 5.5 . Code written for Claude Haiku 4.5 can break on Claude Haiku 5.5. Manual extended thinking ( budget_tokens ), the sampling parameters temperature , top_p , and top_k , and assistant message prefill can each return a 400 error. computer_20250124 also returns a 400 error: use the computer_toolset_20260801 toolset on the Claude API and Google Cloud, or computer_20251124 on Amazon Bedrock. A request that sends thinking blocks back after a change to system , tools , or earlier turns can also return a 400 error. Adaptive thinking is on by default, so a response can begin with thinking blocks, and their text is omitted unless you set thinking.display to &quot;summarized&quot; . The same text also counts as more tokens. See the migration guide for each change. For model-specific prompting patterns, see Prompting Claude Haiku 5.5 . The Python and TypeScript SDKs now include classes, in beta, for the browser use tool and the computer use tool . You subclass one and write one method per tool against your own browser or desktop automation. The SDK runs the tool loop, the URL and file policies you set for the browser, and your approval callback. See Browser and computer use with the SDK toolsets . Claude Max and Team plans now include monthly API credits. To learn how to claim them, see API credits for Max and Team plans . In Claude Managed Agents, a cloud environment with limited networking now also applies its allowed_hosts to the web_search and web_fetch tools. A web_fetch call for a URL on a host that allowed_hosts does not match returns a url_not_allowed error result to the agent. web_search omits results from such hosts. When allowed_hosts lists no hosts, neither tool returns a page or a search result. allow_package_managers and allow_mcp_servers add no hosts for these tools. To let the tools reach a host, add it to allowed_hosts , which also opens it to the sandbox. unrestricted networking and self-hosted environments do not limit these tools. See Environment networking . With limited networking, creating a session fails with a 400 error when an enabled web tool&#x27;s allowed_domains has an entry not within allowed_hosts . So does a session update that adds such an entry. An allowed_hosts entry matches one exact host unless it starts with *. , so docs.example.com is not within [&quot;example.com&quot;] . To fix the error, add the host to allowed_hosts or remove the entry from allowed_domains . See Restrict web search and web fetch domains . In Claude Managed Agents, the web_fetch tool now fetches only URLs that have already appeared in the session, for example in the text of a user message, in a web_search result, or in a page that web_fetch returned earlier. This reduces the risk of data exfiltration. A URL that appears only in Claude&#x27;s own output, the agent&#x27;s system prompt, an attached document, or the output of a tool such as bash , read , or an MCP tool does not count: a web_fetch call for it returns a url_not_in_prior_context error result to the agent.

# Anthropic & Claude API — What's New (2026-09-14)

## Model & API Changes

- Managed Agents permission policies now include an `auto` mode where the server evaluates each tool/MCP call and runs, denies, or pauses it for approval, with the evaluation reported on `agent.tool_use`/`agent.mcp_tool_use` events.
- Per-message effort changes are now in beta on Google Cloud for Claude Fable 5.1, Mythos 5.1, and Opus 5, using the same beta header as the Claude API version.
- Claude Fable 5.1 and Claude Mythos 5.1 launched with a 1M token context window, 128k max output, always-on adaptive thinking, and cheaper cache reads ($0.25/MTok).
- On Fable 5.1 and Mythos 5.1, `tool_choice` types `any` and `tool` are no longer supported and return a 400 error; use strict tool use or structured outputs instead.
- Thinking blocks from Fable 5.1/Mythos 5.1 can only be replayed to the same or newer model, and for new accounts the API now rejects (400) a replayed block if anything earlier in the context changed.
- Turn-scoped system messages and a new `thinking.display: "updates"` value are now in beta, the latter surfacing brief progress updates as text between tool calls.
- Output from Fable 5.1/Mythos 5.1 is now watermarked, and code-execution-generated media retrieved via the Files API carries C2PA content credentials.
- You can create personal keys and service-account API keys in the Console that inherit the linked account's permissions and can be scoped to a workspace or used org-wide.
- The Admin API, Compliance API session endpoints, computer use/browser use toolsets, Files API, and Agent Skills API have all moved out of beta (no beta header required, though old headers still work).
- Claude Managed Agents sessions can now set spend budgets, consult an "advisor" model mid-turn, control inference data residency, load skills from a mounted GitHub repo, and attach memory stores in self-hosted sandboxes.
- Web search/fetch tools for Managed Agents can now be restricted to allowed/blocked domains.
- Claude Opus 4.1 has been retired; all API requests to it now error.
- Introductory Sonnet 5 pricing ($2/$10 per MTok) is now permanent, canceling the planned September price increase.

## SDK Changes

- Python SDK reached v1.0, migrating its HTTP layer from `httpx` to a maintained fork `httpx2`, requiring Python 3.10+, and dropping long-deprecated surface (legacy Text Completions API, `temperature`/`top_p`/`top_k` on Messages, client-side compaction control).
- Python SDK 1.5.0 adds auto-mode tool permissions, `Message.to_param()`/`BetaMessage.to_param()` helpers, new credential error types, and support for passing tool objects directly into `messages.create`/`parse`/`stream`/`count_tokens`.
- `client.beta.files` and `client.beta.skills` no longer send beta headers and now match the stable `client.files`/`client.skills` shapes; `beta.skills.delete()` now deletes all versions of a Skill.
- The Admin API is now available in the `ant` CLI and Python, TypeScript, C#, Go, Java, PHP, and Ruby SDKs under `client.beta.organization`.
- The `ant` CLI added `ant apply` for managing agents/environments/skills/memory/deployments as code, and `ant beta:sessions connect` to attach a terminal to a live Managed Agents session.

## Bug Fixes

- Python SDK: `extra_body` is now merged before client hooks run.
- Python SDK: credential files are now rejected if readable by group or others.
- Python SDK: streaming no longer leaves partial tool-input JSON on content blocks.
- Python SDK: `parsed_output` is no longer included when dumping text blocks.

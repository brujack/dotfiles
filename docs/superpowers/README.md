## Backlog

Ideas approved for future specs, in no particular order:

| Feature                                                                             | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| npm global pin bump path                                                            | The three npm pins added in PR dotfiles#192 (`JSCPD_VER`, `FIRECRAWL_CLI_VER`, `EXA_MCP_SERVER_VER`) are bumped by hand — `./setup_env.sh -t check-versions` cannot cover them. Measured 2026-07-29: jscpd works (`releases/latest` 5.0.14 matches npm exactly); firecrawl-cli publishes no GitHub releases at all; exa-mcp-server is actively unsafe to wire in — its `--version` starts the MCP server rather than printing a version, so the checker would hang. A fix needs a per-tool version source (npm registry query) rather than the existing GitHub-releases path. |
| `includeIf "gitdir:"` hooksPath pins stay probe-cwd-scoped | Follow-up to the include-borne pin fix (dotfiles#198), which made `_git_hooks_hookspath_offenders` read `--includes`. Unconditional `[include]` pins are now caught at any cwd; a conditional `includeIf "gitdir:..."` pin is caught only when the probe's cwd already satisfies the condition, because the probe runs once per sweep rather than once per discovered repo (deliberate — the pre-loop position is what lets each repo's rc=2 be attributed to the pin instead of counted as its own gap). Strictly more than `--no-includes` ever saw, so not a regression. Closing it means giving the probe repo context (`git -C <dir> config ...` per discovered repo), which restructures the sweep. Not currently reachable on this fleet: no tracked `.gitconfig_*` sets `hooksPath`, and the live boxes report unset at both scopes — measured 2026-08-05. Re-price if a machine-local include ever carries one. |
| `make lint` cannot see the extensionless hooks | `SHELL_FILES := $(shell find . -name "*.sh" ...)` matches only `.sh`, so `scripts/pre-push` and `scripts/commit-msg` — the hooks that gate every commit and push — are never shellchecked by `make lint`. Found by `security-review` during dotfiles#195, which had to run `shellcheck --shell=bash scripts/pre-push` explicitly to review them at all. Same theme as #195 itself: the gate cannot see its own implementation. Fix is adding the two extensionless paths to `SHELL_FILES`; check first whether shellcheck's `--shell=bash` is needed since they have a shebang but no extension. |
| pre-push suite runtime is the real lever, not the predicate | Measured during dotfiles#195: `make test` is **9m34s** (574s, uncontended, 1128 tests) and the fail-closed trigger raises the trigger rate from 35% to 47% over the last 400 commits — ~47 additional triggering commits, of which ~26 touch files `make test` demonstrably cannot read (auto-generated digest state, `.warp/settings.toml`, `manifests/*.yaml`, `renovate.json`). **Do not widen the inert set to reclaim this** — that is the allowlist creep ADR-0017 rejects, and the direction is deliberate (a false skip costs a red CI plus a round trip; a false trigger costs local time). The durable fix is making the suite faster: parallelism, or splitting a fast subset from the full run. |
| Fail-closed widened the fleet's bats/zsh dependency | `make test` hard-errors without bats (`$(error bats not found)`) and `make lint` runs `zsh -n` unconditionally (unlike shellcheck, which is guarded by `if [ -n $(SHELLCHECK) ]`). Under the old allowlist a `Brewfile`- or `starship.toml`-only push succeeded on a machine lacking either; post-dotfiles#195 it is blocked. Most relevant to the Windows/WSL2 backup-of-last-resort box, which is reached under time pressure. `--no-verify` is the escape hatch, but the failure mode is newly reachable. Consider guarding `zsh -n` the way shellcheck already is. |
| `core.quotePath` defeats the pre-push path anchors | `git diff --name-only` C-quotes paths containing non-ASCII bytes, emitting e.g. `"scripts/caf\303\251.sh"` with a leading double-quote, which no `^`-anchored alternative matches. Under the fail-closed trigger the direction is now safe (an unmatched path is non-inert, so it *triggers*) — but the inert set's own anchors are still evaluated against the quoted form, so a non-ASCII `.md` would trigger unnecessarily rather than skip. Pre-existing since before dotfiles#195 and currently unreachable: 0 of 392 tracked paths contain non-ASCII bytes. One-line hardening if ever wanted: `git -c core.quotePath=false diff --name-only`. Raised independently by `security-review` and a code-quality reviewer during dotfiles#195, both correctly declining to treat it as blocking. |
| Maintainability pass (re-scope needed — original premise falsified) | Original note said "once the ai-config maintainability gate ships, run a worldclass pass in this repo against its thresholds." The gate **has** shipped, and it ran on dotfiles#195 — returning **SKIP**, because its blocking surface is Python `ruff` C901/PLR09xx and Rust `clippy`, and this repo is bash. There are no mechanical thresholds here to run a pass *against*, so the row cannot be executed as written. Two real options: (a) close this row and instead act on the concrete bash findings the gate's report-only lens did produce — chiefly the `install_git_hooks_all_repos` length row below; or (b) spec a bash threshold set for `maintainability-review` in ai-config first, which makes this row a dependency on that work rather than on the gate's existence. Not a free-standing task either way. |
| Coverage include-list still misses `lib/package_capture.sh`, and `config/` entirely | `scripts/run-bash-coverage.sh` names each instrumented file in a hand-maintained `INCLUDE_FILES` array with nothing reconciling it against `lib/*.sh`. `lib/git_hooks.sh` was silently excluded until PR #189 added it — the gate would have reported 90% while measuring none of a 400-line subsystem. `lib/package_capture.sh` is still absent and `config/` is not measured at all. Deliberately not folded into #189: adding an unmeasured file can drop the total below the 90% CI floor and turn a hygiene fix into a merge blocker, so it needs its own change with its own measurement. Fix should also consider deriving the list from `lib/*.sh` rather than maintaining it by hand.                                                                   |
| Deep-dive bug hunt (fleet-critical)                                                 | **Suitable for an overnight cataloguing run.** This repo deploys and controls every dev machine, so a silent defect here is a fleet-wide defect. Two leads are already reproduced (not hypotheses): `run_update`'s exit code is decorative across all 17 sections, and `GIT_DIR` is stripped in exactly one lib file while `git_sync.sh` and `legacy_rsync.sh` do `git push` over SSH and `rsync --delete` without it. **Full running dossier — leads, defect classes, and the techniques that found them — lives in [`ai-config/docs/knowledge/dotfiles-bug-hunt-leads.md`](https://github.com/brujack/ai-config/blob/master/docs/knowledge/dotfiles-bug-hunt-leads.md). Append there as findings accumulate; do not duplicate them into this row.**            |

## Adding a new entry

When a new spec or plan is created, add a row to the All Plans table. Set status to **In Progress** when implementation starts, **Done** when the PR merges. Also add a `> **Status: DONE**` banner at the top of the plan file once complete. Move backlog items to the All Plans table when their spec is written (remove the backlog row).

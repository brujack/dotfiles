| npm global pin bump path                                                                 | The three npm pins added in PR dotfiles#192 (`JSCPD_VER`, `FIRECRAWL_CLI_VER`, `EXA_MCP_SERVER_VER`) are bumped by hand — `./setup_env.sh -t check-versions` cannot cover them. Measured 2026-07-29: jscpd works (`releases/latest` 5.0.14 matches npm exactly); firecrawl-cli publishes no GitHub releases at all; exa-mcp-server is actively unsafe to wire in — its `--version` starts the MCP server rather than printing a version, so the checker would hang. | `includeIf "gitdir:"` hooksPath pins stay probe-cwd-scoped                               | Follow-up to the include-borne pin fix (dotfiles#198), which made `_git_hooks_hookspath_offenders` read `--includes`. Unconditional `[include]` pins are now caught at any cwd; a conditional `includeIf "gitdir:..."` pin is caught only when the probe's cwd already satisfies the condition, because the probe runs once per sweep rather than once per discovered repo (deliberate — the pre-loop position is what lets each repo's rc=2 be attributed to the pin instead of counted as its own gap). Strictly more than `--no-includes` ever saw, so not a regression. Closing it means giving the probe repo context (`git -C <dir> config ...` per discovered repo), which restructures the sweep. Not currently reachable on this fleet: no tracked `.gitconfig_*` sets `hooksPath`, and the live boxes report unset at both scopes — measured 2026-08-05. Re-price if a machine-local include ever carries one.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| pre-push suite runtime is the real lever, not the predicate                              | Measured during dotfiles#195: `make test` is **9m34s** (574s, uncontended, 1128 tests) and the fail-closed trigger raises the trigger rate from 35% to 47% over the last 400 commits — ~47 additional triggering commits, of which ~26 touch files `make test` demonstrably cannot read (auto-generated digest state, `.warp/settings.toml`, `manifests/*.yaml`, `renovate.json`). **Do not widen the inert set to reclaim this** — that is the allowlist creep ADR-0017 rejects, and the direction is deliberate (a false skip costs a red CI plus a round trip; a false trigger costs local time). The durable fix is making the suite faster: parallelism, or splitting a fast subset from the full run.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `core.quotePath` defeats the pre-push path anchors                                       | `git diff --name-only` C-quotes paths containing non-ASCII bytes, emitting e.g. `"scripts/caf\303\251.sh"` with a leading double-quote, which no `^`-anchored alternative matches. Under the fail-closed trigger the direction is now safe (an unmatched path is non-inert, so it _triggers_) — but the inert set's own anchors are still evaluated against the quoted form, so a non-ASCII `.md` would trigger unnecessarily rather than skip. Pre-existing since before dotfiles#195 and currently unreachable: 0 of 392 tracked paths contain non-ASCII bytes. One-line hardening if ever wanted: `git -c core.quotePath=false diff --name-only`. Raised independently by `security-review` and a code-quality reviewer during dotfiles#195, both correctly declining to treat it as blocking.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Maintainability pass (re-scope needed — original premise falsified)                      | Original note said "once the ai-config maintainability gate ships, run a worldclass pass in this repo against its thresholds." ## Adding a new entry

When a new spec or plan is created, add a row to the All Plans table. Set status to **In Progress** when implementation starts, **Done** when the PR merges. Also add a `> **Status: DONE**` banner at the top of the plan file once complete. Move backlog items to the All Plans table when their spec is written (remove the backlog row).

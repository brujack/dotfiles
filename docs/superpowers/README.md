## Backlog

| Feature                                                                             | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Git-hook self-coverage gap                                                          | `scripts/pre-push`'s own trigger regex `'\.(sh|bats)$|^Makefile$|^tests/'` does not match extensionless `scripts/pre-push` or `scripts/commit-msg`, so the hook does not test itself — an edit to either pushes without running the suite. CI backstops it. Fix is one character class (`|^scripts/`). Pairs with the git-env hygiene follow-up (15 hand-copied unsets). Found during dotfiles#191 bug-scan.                                                                                                                                                                                                                                                                                                                                                     |
| npm global pin bump path                                                            | The three npm pins added in PR dotfiles#192 (`JSCPD_VER`, `FIRECRAWL_CLI_VER`, `EXA_MCP_SERVER_VER`) are bumped by hand — `./setup_env.sh -t check-versions` cannot cover them. Measured 2026-07-29: jscpd works (`releases/latest` 5.0.14 matches npm exactly); firecrawl-cli publishes no GitHub releases at all; exa-mcp-server is actively unsafe to wire in — its `--version` starts the MCP server rather than printing a version, so the checker would hang. A fix needs a per-tool version source (npm registry query) rather than the existing GitHub-releases path. |
| Maintainability pass                                                                | Once the ai-config maintainability gate (2026-07-24 spec) ships, run a worldclass pass in this repo against its thresholds — not scheduled yet.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Coverage include-list still misses `lib/package_capture.sh`, and `config/` entirely | `scripts/run-bash-coverage.sh` names each instrumented file in a hand-maintained `INCLUDE_FILES` array with nothing reconciling it against `lib/*.sh`. `lib/git_hooks.sh` was silently excluded until PR #189 added it — the gate would have reported 90% while measuring none of a 400-line subsystem. `lib/package_capture.sh` is still absent and `config/` is not measured at all. Deliberately not folded into #189: adding an unmeasured file can drop the total below the 90% CI floor and turn a hygiene fix into a merge blocker, so it needs its own change with its own measurement. Fix should also consider deriving the list from `lib/*.sh` rather than maintaining it by hand.                                                                   |
| Deep-dive bug hunt (fleet-critical)                                                 | **Suitable for an overnight cataloguing run.** This repo deploys and controls every dev machine, so a silent defect here is a fleet-wide defect. Two leads are already reproduced (not hypotheses): `run_update`'s exit code is decorative across all 17 sections, and `GIT_DIR` is stripped in exactly one lib file while `git_sync.sh` and `legacy_rsync.sh` do `git push` over SSH and `rsync --delete` without it. **Full running dossier — leads, defect classes, and the techniques that found them — lives in [`ai-config/docs/knowledge/dotfiles-bug-hunt-leads.md`](https://github.com/brujack/ai-config/blob/master/docs/knowledge/dotfiles-bug-hunt-leads.md). Append there as findings accumulate; do not duplicate them into this row.**            |

## Adding a new entry

When a new spec or plan is created, add a row to the All Plans table. Set status to **In Progress** when implementation starts, **Done** when the PR merges. Also add a `> **Status: DONE**` banner at the top of the plan file once complete. Move backlog items to the All Plans table when their spec is written (remove the backlog row).

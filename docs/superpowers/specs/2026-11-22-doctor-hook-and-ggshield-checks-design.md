# Doctor checks: installed hooks and ggshield authentication

**Date:** 2026-11-22
**Status:** Draft (revised after Step 8 round 1)
**Source:** security audit 2026-11-16, findings F5, F6 and F10 (ai-config
`docs/knowledge/dotfiles-security-audit-2026-11-16.md`).

## Problem

Three findings share one gap: `setup_env.sh -t doctor` says nothing about whether the
local secret-scan and push gates can run.

- **F5.** No doctor check reads the installed hooks. `_git_hooks_check_complete`
  (`lib/git_hooks.sh`) exists, but only the `-t update` and `setup_user` repair sweep calls
  it, and that sweep repairs gaps without reporting them as a health state.
- **F6.** `_git_hooks_check_complete` tests `[[ -x ]]` only. A hook that is present and
  executable but is a stale copy, another hook's script, or a generated shim that cannot
  run on this machine, passes.
- **F10.** Nothing checks that `ggshield` resolves and holds a working API key. The
  pre-commit hook degrades to a stderr warning when ggshield is missing or
  unauthenticated (ADR-0052), and that warning scrolls past on every commit.

What this design buys is an on-demand health signal: the operator runs `-t doctor` on a
provisioned host and gets a FAIL with a working remedy. It does not add a persistent or
scheduled signal (operator decision 2026-11-22: doctor only).

ai-config ADR-0055 added `make check-hooks` and a SessionStart drift warning, but for
ai-config's own three hooks only. ai-config `ci.md` still records, fleet-wide, "Nothing
reports an uninstalled or stale hook."

## Premise measurements (2026-11-22)

- **Hooks, `claude`.** 27 mandated hooks (`pre-commit`, `pre-push`, `commit-msg` in each of
  the nine `HOOK_EXPECTED_REPOS`), compared by absolute-path `cmp` against every tracked
  file and by symlink resolution. 26 are a symlink to, or a byte-identical copy of,
  exactly one tracked file, and that file is always named `<hook>` or `<hook>-hook.sh`
  (under `scripts/` in eight repos, `ansible/scripts/` in terraform_ansible). The Step 8
  ergonomics lens ran the same survey on the Studio and `workstation` with the same
  result. The Windows box was not surveyed.
- **The 27th is generated, not stale.** state-ledger's `pre-commit` starts
  `# File generated by pre-commit: https://pre-commit.com`. state-ledger's
  `install-hooks` installs only `pre-push` and `commit-msg` and prints
  `(pre-commit hook is installed by 'ledger init')`; `ledger init` runs
  `pre-commit install` (state-ledger ADR-0006). The shim pins
  `INSTALL_PYTHON=/Users/bruce/.pyenv/versions/ansible/bin/python` on `claude`, a Linux
  box: the interpreter does not exist, so the shim falls back to `command -v pre-commit`
  and exits 1 where that does not resolve (`ssh host 'git commit'`, cron). That is the
  live F6 instance: present, executable, and not runnable as installed.
- **ggshield 1.56.1 exit codes, by command** (measured on `claude` with the real key, with
  `GITGUARDIAN_API_KEY=invalid-fixture-key`, and with `HOME`/`XDG_CONFIG_HOME` pointing at
  an empty directory):

  | command               | good key | bad key | no key |
  | --------------------- | -------- | ------- | ------ |
  | `ggshield api-status` | 0        | **0**   | 3      |
  | `ggshield quota`      | 0        | 128     | 3      |

  `api-status` exits 0 for a rejected key and prints `Status: unhealthy (Invalid API
key.)`. A check built on it passes the case F10 exists to catch. `quota` separates all
  three. A dead proxy (`HTTPS_PROXY=http://127.0.0.1:9`) made `api-status` hit a 15 s
  `timeout` (rc 124).

## Design

Two new doctor arms, run by `run_doctor` in this order, immediately after
`_doctor_check_hooks_path`:

```
_doctor_check_hooks_path
_doctor_check_git_hooks      # new
_doctor_check_ggshield       # new
_doctor_check_versions
```

Neither arm writes anything. Neither changes `-t update`, `setup_user`, the repair sweep,
or any hook script.

### 1. `_doctor_check_git_hooks` (F5, F6)

Prints the heading `Git hooks:`. For each name in `HOOK_EXPECTED_REPOS`, with
`dir=${PERSONAL_GITREPOS}/<name>` and `<remedy-dir>` the directory
`_git_hooks_target_dir` prints for it (the repo directory when it prints nothing):

| state                                                          | line                                                                                                                                             |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `dir` absent                                                   | `printf '  - %s: not cloned on this host\n'` (info; neither PASS nor FAIL)                                                                       |
| `dir/.git` not a directory, or `git rev-parse --git-dir` fails | nothing (same rule as `_git_hooks_gap_repos`)                                                                                                    |
| `_git_hooks_dir` fails                                         | `doctor_fail "<name>: no hooks directory — remedy: make -C <remedy-dir> install-hooks"`                                                          |
| any mandated hook not `-x`                                     | `doctor_fail "<name>: missing <hooks> — remedy: <per-hook remedy>"`                                                                              |
| a hook's identity is `foreign`                                 | `doctor_fail "<name>: <hook> is not this repo's <hook> script — remedy: <per-hook remedy>"`                                                      |
| a hook `stale`, repo on `master` or `main`                     | `doctor_fail "<name>: <hook> is stale — remedy: <per-hook remedy>"`                                                                              |
| a hook `stale`, repo on any other branch or detached           | `doctor_warn "<name>: <hook> differs from <branch> (expected off the default branch)"`                                                           |
| a hook `worktree`                                              | `doctor_warn "<name>: <hook> runs from worktree <path> — remedy: <per-hook remedy>"`                                                             |
| a hook `generated-broken`                                      | `doctor_fail "<name>: <hook> is a pre-commit shim that cannot run here (<reason>) — remedy: cd <dir> && pre-commit install"`                     |
| a hook `generated-fallback`                                    | `doctor_warn "<name>: <hook> pre-commit shim runs only where pre-commit is on PATH (<python> missing) — remedy: cd <dir> && pre-commit install"` |
| identity unreadable (rc 2)                                     | `doctor_fail "<name>: cannot verify hooks (<reason>)"`                                                                                           |
| every hook `-x` and `match` or `generated`                     | `doctor_pass "<name>: pre-commit pre-push commit-msg installed"`                                                                                 |

One line per repo when the repo is healthy; one line per faulty hook otherwise.
`<hooks>` is the space-joined list `_git_hooks_check_complete` prints. `<per-hook remedy>`
is `cd <dir> && pre-commit install` for a hook whose repo tracks `.pre-commit-config.yaml`
and has no tracked `<hook>` or `<hook>-hook.sh`, and `make -C <remedy-dir> install-hooks`
otherwise.

After the loop, when no listed repo was found under `PERSONAL_GITREPOS` at all, the arm
calls `doctor_fail "no listed repo found under <PERSONAL_GITREPOS> — check GITREPOS"`. A
wrong `PERSONAL_GITREPOS` therefore cannot read as nine healthy repos.

The default-branch test reads the branch name with `git symbolic-ref --short -q HEAD`
and treats only the literal names `master` and `main` as default. It does not read
`refs/remotes/origin/HEAD`, which is a clone-time cache (core.md git-workflow-038).

#### `_git_hooks_identity <repo_dir> <hook_name> <hook_path>` (new, `lib/git_hooks.sh`)

The **source candidates** are the tracked paths of the repo whose basename is exactly
`<hook_name>` or `<hook_name>-hook.sh`, read from `git ls-files` with the four-variable
strip (`env -u GIT_DIR -u GIT_WORK_TREE -u GIT_COMMON_DIR -u GIT_INDEX_FILE`). Matching
by name is what stops a `pre-commit` that is a copy of the repo's own `pre-push` from
passing; it needs no per-repo map.

Prints one word and returns:

- **`match`, rc 0.** `hook_path` is a symlink whose fully resolved target is a source
  candidate in the repo's main working tree, or a regular file `cmp -s`-identical to the
  on-disk content of a source candidate.
- **`generated`, rc 0.** `hook_path` is a regular file whose first five lines contain
  `# File generated by pre-commit`, the repo tracks `.pre-commit-config.yaml`, and the
  file's `INSTALL_PYTHON=` value is an executable file on this machine.
- **`generated-fallback`, rc 1.** As `generated`, but `INSTALL_PYTHON` is not executable
  here and `command -v pre-commit` resolves in doctor's own environment.
- **`generated-broken`, rc 1.** As `generated`, but `INSTALL_PYTHON` is not executable and
  `pre-commit` does not resolve, or the repo does not track `.pre-commit-config.yaml`, or
  the file has no `INSTALL_PYTHON=` line. The printed reason names which.
- **`worktree`, rc 1.** A symlink resolving inside a linked worktree of the same repo
  (from `git worktree list --porcelain`).
- **`stale`, rc 1.** A regular file not generated and matching no source candidate, or a
  symlink to a path inside the main working tree that is not a source candidate.
- **`foreign`, rc 1.** A symlink resolving outside the repo and all its worktrees.
- **rc 2,** printing a reason. `git ls-files` fails, or `hook_path` cannot be read.

A symlink is resolved through every level and compared as a physical path (`pwd -P`), so
a symlinked `PERSONAL_GITREPOS` cannot turn a match into `foreign`.

`_git_hooks_check_complete` is not changed: the repair sweep keeps its `-x`-only
semantics.

### 2. `_doctor_check_ggshield` (F10)

Prints the heading `ggshield:`.

**Resolution.** Same order as `scripts/pre-commit-hook.sh`: `GGSHIELD_BIN`, then
`command -v ggshield`, then each word of `GGSHIELD_FALLBACK_PATHS` (default
`/opt/homebrew/bin/ggshield /usr/local/bin/ggshield /home/linuxbrew/.linuxbrew/bin/ggshield`).
Doctor carries its own copy of this logic in `lib/helpers.sh`; `scripts/pre-commit-hook.sh`
is not touched. Sharing a `lib/` file was rejected (see below). A test extracts the
fallback default list from both files and asserts they are identical, so the two cannot
drift.

**Doctor lines:**

| condition                             | line                                                                                                  |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `GGSHIELD_BIN` set but not executable | `doctor_fail "GGSHIELD_BIN=<value> is not executable"`                                                |
| nothing resolves                      | `doctor_fail "not installed — the pre-commit secret scan cannot run — remedy: brew install ggshield"` |
| no `timeout` binary resolvable        | `doctor_warn "<path>: found; API key not verified (no timeout binary)"`                               |
| `quota` rc 0                          | `doctor_pass "<path>: authenticated"`                                                                 |
| `quota` rc 3                          | `doctor_fail "<path>: no API key — remedy: ggshield auth login"`                                      |
| `quota` rc 124                        | `doctor_warn "<path>: could not verify the API key: no answer in <N>s"`                               |
| `quota` any other non-zero rc         | `doctor_fail "<path>: API key rejected or check failed (rc <rc>) — remedy: ggshield auth login"`      |

The probe runs
`"${_timeout_bin}" "${_DOCTOR_PROBE_TIMEOUT:-10}" "${_ggshield}" quota </dev/null >/dev/null 2>&1`,
with `_timeout_bin` resolved the same way `_doctor_check_dev_tools` resolves it, through
`_TIMEOUT_FALLBACK_PATHS`. Neither stdout nor stderr of `ggshield` reaches doctor's
output, so no key material or account detail can. `quota` is a read-only endpoint; no
scan runs and no scan quota is consumed.

## Testing

- **Hook fixtures.** Built under `BATS_TEST_TMPDIR` with `PERSONAL_GITREPOS` and
  `HOOK_EXPECTED_REPOS` pointed at them: one `git init` repo per state, tracking
  `scripts/pre-commit-hook.sh`, `scripts/pre-push` and `scripts/commit-msg`. States:
  absent, all repos absent, linked worktree only, no hooks dir, missing hook,
  non-executable hook, symlink match (absolute and relative), copy match, `-hook.sh`
  match, stale copy on `master`, stale copy on a branch, cross-hook swap (`pre-commit`
  holding `scripts/pre-push`'s bytes), symlink into a linked worktree, symlink to another
  fixture repo, symlink to an untracked file, an empty hook file, an unreadable hook.
- **Generated-shim fixtures.** A shim written from a template with the real header:
  `INSTALL_PYTHON` pointing at an executable stub (`generated`), at a missing path with a
  `pre-commit` stub on a scoped `PATH` (`generated-fallback`), at a missing path with no
  `pre-commit` (`generated-broken`), and a repo without `.pre-commit-config.yaml`
  (`generated-broken`).
- **Positive control** for identity: a copy that passes turns into a `stale` FAIL after a
  one-byte edit to the installed hook, in the same test.
- **ggshield.** A stub at `tests/stubs/ggshield-stub`, reached only through `GGSHIELD_BIN`
  and `GGSHIELD_FALLBACK_PATHS`, with exit code and sleep read from `STUB_GGSHIELD_*`.
  Cases: rc 0, 3, 128, 1, timeout (`_DOCTOR_PROBE_TIMEOUT=1`, stub sleeps 5), not found,
  non-executable override, and no `timeout` binary (`_TIMEOUT_FALLBACK_PATHS` at a missing
  path and a scoped `PATH` of stubs).
- **Leak check.** The stub prints a fixed fake key on stdout and stderr and records its
  invocation. A test asserts the invocation was recorded and that doctor's output does
  not contain the key.
- **Drift check.** A test asserts the `GGSHIELD_FALLBACK_PATHS` default list in
  `lib/helpers.sh` equals the one in `scripts/pre-commit-hook.sh`.
- **Wiring.** A `run_doctor` test with both arms stubbed asserts their headings appear
  between `Git hooks path` and the versions section.

## Rejected alternatives

- **`ggshield api-status`** as the auth probe. Measured above: it exits 0 for a rejected
  key.
- **Moving the resolver into a shared `lib/ggshield.sh` sourced by the pre-commit hook.**
  The hook `cd`s into the repository being committed, so it would source the file from
  the tree under scan. In a fixture repo, or a worktree branched before the change,
  `source` fails and `resolve_ggshield` returns 127 with an empty path, which reaches
  the hook's announce-and-continue branch: the scan is skipped and the commit exits 0. A
  branch could also edit the file to disable its own scan. Step 8 risk lens, round 1.
- **"Byte-identical to any tracked file."** It passes a cross-hook swap and cannot model
  a generated shim, which made state-ledger's `pre-commit` a permanent FAIL whose remedy
  (`install-hooks`) never installs it. Step 8, all three lenses, round 1.
- **A per-repo `installed-name:source` map** (ADR-0055's `MANAGED_HOOKS`). Nine maps
  maintained in dotfiles for repos it does not own. The name rule above covers all 26
  copied or linked hooks on three machines without one.
- **Comparing against `HEAD`'s blob** instead of the working tree. ADR-0055 compares
  against the working tree, because that is what `install-hooks` copies.
- **Extending `_git_hooks_check_complete` to check identity.** It changes what the repair
  sweep repairs, which the operator ruled out of scope.
- **Presence-only for generated hooks**, or moving state-ledger to a tracked `pre-commit`
  first. Operator chose the shim check (A), 2026-11-22.

## Requirements

- **R1.** `run_doctor` calls `_doctor_check_git_hooks` and then `_doctor_check_ggshield`, both immediately after `_doctor_check_hooks_path` and before `_doctor_check_versions`.
- **R2.** `_doctor_check_git_hooks` prints the heading `Git hooks:` and, for each `HOOK_EXPECTED_REPOS` name whose directory under `PERSONAL_GITREPOS` is absent, prints `  - <name>: not cloned on this host` without calling `doctor_pass`, `doctor_warn` or `doctor_fail`.
- **R3.** When none of the `HOOK_EXPECTED_REPOS` directories exists under `PERSONAL_GITREPOS`, `_doctor_check_git_hooks` calls `doctor_fail "no listed repo found under <PERSONAL_GITREPOS> — check GITREPOS"`.
- **R4.** `_doctor_check_git_hooks` prints nothing for a listed name whose `.git` is not a directory or whose `git rev-parse --git-dir` fails.
- **R5.** When `_git_hooks_dir` fails for a repo, `_doctor_check_git_hooks` calls `doctor_fail "<name>: no hooks directory — remedy: make -C <remedy-dir> install-hooks"`, where `<remedy-dir>` is the directory `_git_hooks_target_dir` prints for that repo, or the repo directory when it prints nothing.
- **R6.** When any of `pre-commit`, `pre-push`, `commit-msg` is not executable in a repo's hooks directory, `_doctor_check_git_hooks` calls `doctor_fail "<name>: missing <hooks> — remedy: <per-hook remedy>"`, `<hooks>` being the space-joined names `_git_hooks_check_complete` prints.
- **R7.** `<per-hook remedy>` is `cd <dir> && pre-commit install` when the repo tracks `.pre-commit-config.yaml` and has no tracked file named `<hook>` or `<hook>-hook.sh`, and `make -C <remedy-dir> install-hooks` otherwise.
- **R8.** `_git_hooks_identity <repo_dir> <hook_name> <hook_path>` takes as source candidates only tracked paths whose basename is `<hook_name>` or `<hook_name>-hook.sh`, and prints `match` and returns 0 when `hook_path` is a symlink resolving to a source candidate in the main working tree or a regular file `cmp -s`-identical to a source candidate's on-disk content.
- **R9.** `_git_hooks_identity` prints `generated` and returns 0 for a regular file whose first five lines contain `# File generated by pre-commit`, in a repo tracking `.pre-commit-config.yaml`, whose `INSTALL_PYTHON=` value is an executable file.
- **R10.** For such a file whose `INSTALL_PYTHON` is not executable, `_git_hooks_identity` prints `generated-fallback` and returns 1 when `command -v pre-commit` resolves, and prints `generated-broken` with a reason and returns 1 when it does not; it also prints `generated-broken` with a reason and returns 1 when the repo does not track `.pre-commit-config.yaml` or the file has no `INSTALL_PYTHON=` line.
- **R11.** `_git_hooks_identity` prints `worktree` and returns 1 for a symlink resolving inside a linked worktree of the same repo; `foreign` and 1 for a symlink resolving outside the repo and all its worktrees; `stale` and 1 for a non-generated regular file matching no source candidate or a symlink to a non-candidate path in the main working tree.
- **R12.** `_git_hooks_identity` returns 2 and prints a reason when `git ls-files` fails or `hook_path` is unreadable.
- **R13.** With every mandated hook executable, `_doctor_check_git_hooks` maps identities to: `foreign` → `doctor_fail "<name>: <hook> is not this repo's <hook> script — remedy: <per-hook remedy>"`; `stale` → `doctor_fail "<name>: <hook> is stale — remedy: <per-hook remedy>"` when `git symbolic-ref --short -q HEAD` prints `master` or `main`, else `doctor_warn "<name>: <hook> differs from <branch> (expected off the default branch)"` with `<branch>` `detached HEAD` when detached; `worktree` → `doctor_warn "<name>: <hook> runs from worktree <path> — remedy: <per-hook remedy>"`.
- **R14.** `generated-broken` → `doctor_fail "<name>: <hook> is a pre-commit shim that cannot run here (<reason>) — remedy: cd <dir> && pre-commit install"`; `generated-fallback` → `doctor_warn "<name>: <hook> pre-commit shim runs only where pre-commit is on PATH (<python> missing) — remedy: cd <dir> && pre-commit install"`; identity rc 2 → `doctor_fail "<name>: cannot verify hooks (<reason>)"`; all three `match` or `generated` → `doctor_pass "<name>: pre-commit pre-push commit-msg installed"`.
- **R15.** `_git_hooks_check_complete` and `scripts/pre-commit-hook.sh` are unchanged.
- **R16.** `_doctor_check_ggshield` prints the heading `ggshield:` and resolves ggshield in the order `GGSHIELD_BIN`, `command -v ggshield`, then each word of `GGSHIELD_FALLBACK_PATHS` (default `/opt/homebrew/bin/ggshield /usr/local/bin/ggshield /home/linuxbrew/.linuxbrew/bin/ggshield`); a set but non-executable `GGSHIELD_BIN` gives `doctor_fail "GGSHIELD_BIN=<value> is not executable"`, and nothing resolving gives `doctor_fail "not installed — the pre-commit secret scan cannot run — remedy: brew install ggshield"`.
- **R17.** When ggshield resolves and no `timeout` binary resolves through `_TIMEOUT_FALLBACK_PATHS` or `PATH`, `_doctor_check_ggshield` calls `doctor_warn "<path>: found; API key not verified (no timeout binary)"` and runs no ggshield command.
- **R18.** Otherwise `_doctor_check_ggshield` runs `<timeout> "${_DOCTOR_PROBE_TIMEOUT:-10}" <path> quota` with stdin from `/dev/null` and stdout and stderr discarded, and maps rc 0 to `doctor_pass "<path>: authenticated"`, rc 3 to `doctor_fail "<path>: no API key — remedy: ggshield auth login"`, rc 124 to `doctor_warn "<path>: could not verify the API key: no answer in <N>s"`, and any other non-zero rc to `doctor_fail "<path>: API key rejected or check failed (rc <rc>) — remedy: ggshield auth login"`.
- **R19.** A test asserts the `GGSHIELD_FALLBACK_PATHS` default list in `lib/helpers.sh` is identical to the one in `scripts/pre-commit-hook.sh`.
- **R20.** No test reaches the real `ggshield` binary or the network: every `_doctor_check_ggshield` test sets `GGSHIELD_BIN` or `GGSHIELD_FALLBACK_PATHS` to `tests/stubs/ggshield-stub` or a missing path.
- **R21.** A test asserts that the stub recorded its invocation and that a fake key the stub prints on stdout and stderr does not appear in `_doctor_check_ggshield`'s output.
- **R22.** A test installs a byte-identical copy that `_doctor_check_git_hooks` reports as PASS, edits one byte of the installed copy, and asserts the repo then reports `is stale` as a FAIL.
- **R23.** A test installs a `pre-commit` holding the bytes of the fixture repo's tracked `scripts/pre-push` and asserts `_git_hooks_identity` prints `stale` for it.
- **V1.** On `claude`, `./setup_env.sh -t doctor` on the finished branch reports state-ledger's `pre-commit` as `generated-fallback` or `generated-broken` (its `INSTALL_PYTHON` is a `/Users/` path), every other cloned repo PASS, and `ggshield: … authenticated`. ## Multi-Lens Review

Reviewed at commit: `2d179d54` (Step 7 self-review commit, before Step 8 dispatch)

### Goal-Fit

Finding: state-ledger's `pre-commit`, the spec's only live F6 instance, is a pre-commit
framework shim, not a stale copy; the identity rule makes it a permanent FAIL whose
remedy (`install-hooks`) never installs it, and V1 blessed that outcome. Doctor output
persists nowhere, so F10's "no persistent signal" framing overclaimed. If
`PERSONAL_GITREPOS` is wrong, nine "not cloned" PASS lines read as a healthy arm that
measured nothing. Premise verified: 26/27 `cmp` count, `api-status` rc 0 and `quota` rc
128 for a bad key.
Assumption: every mandated hook is installed by its repo's `install-hooks` from a tracked
file. Refuted by state-ledger; settled by reading each repo's `install-hooks` and grepping
installed hooks for `File generated by`.
Disposition: Addressed in this revision. Generated shims get their own identity (operator
chose A, 2026-11-22); "not cloned" is an info line and zero repos found is a FAIL (R2,
R3); the Problem section now claims an on-demand signal only; V1 rewritten.

### Ergonomics

Finding: the state-ledger shim would FAIL doctor's first run on all three development
boxes (survey run on `claude`, the Studio and `workstation`), with a remedy that cannot
clear it, so the operator learns to ignore the arm on day one. Same empty-measure gap as
Goal-fit. Main checkouts lagging origin could make a worktree-installed hook read as stale
on master; not observed.
Assumption: on every development box, every mandated hook other than state-ledger's
`pre-commit` is a symlink to or copy of a tracked file. Confirmed on three boxes; the
Windows box is unsurveyed.
Disposition: Addressed in this revision (same changes as Goal-fit). Windows remains
unsurveyed; V3 covers the Studio and `workstation`.

### Risk

Finding: (1) the state-ledger misdiagnosis, as above; (2) moving the resolver into
`lib/ggshield.sh` sourced from the committed tree fails open: in a fixture or a stale
worktree `source` fails, `resolve_ggshield` returns 127, the hook skips the scan and
exits 0, and a branch could disable its own scan; `tests/scripts/pre_commit_hook.bats`
fixtures have no `lib/`; (3) "identical to any tracked file" passes a cross-hook swap.
Cost measured at 167 ms across nine repos.
Assumption: every mandated hook is installed from a tracked file; refuted by
state-ledger.
Disposition: Addressed in this revision. The hook script is untouched and doctor carries
its own resolver with a drift test (R15, R16, R19); source candidates are name-matched
(R8, R23); generated shims as above.
